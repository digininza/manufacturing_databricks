# Troubleshooting (production support scenarios)

| # | Symptom | Likely cause | Fix |
|---|---|---|---|
| 1 | ADF `Copy_To_Staging` fails with a timeout or `SqlException … network-related` | SHIR node or VPN blip | Automatic (3 retries × 120s). If all retries fail, the run is `FAILED` and the watermark is unchanged. **Rerun `PL_00`**: only failed entities run, with the same frozen window. |
| 2 | `RECONCILIATION FAILED … source_count <> rows_read` | Rows committed *inside* the window after the count, or a source read on a non-snapshot isolation level | Look at the counts in `ctl.ingestion_run_history`. Rerun (same frozen window). If it persists, enable snapshot isolation on the source or count and copy within one snapshot. |
| 3 | `CDC LSN GAP for dbo_production_log` (THROW 50001) | The pipeline was down longer than CDC retention (7 days), so the cleanup job purged unread changes | **Do not reset the watermark blindly.** 1) Full reload of the table (a one-off FULL entity or a backfill query); 2) `EXEC ctl.usp_reset_watermark 'mes_production_log', '<current max LSN>', 'INC-1234 LSN gap full reload'`; 3) silver MERGE absorbs the full reload (newer `_sequence` wins). Consider increasing retention. |
| 4 | Supplier file run fails: `rejected N of M rows exceeds tolerance 2%` | Supplier changed the file layout | Inspect `raw/_rejected/supplier_delivery/<run_id>/`. Contact the supplier. After the corrected file arrives, rerun. |
| 5 | Bronze task fails: `ADF->Bronze count mismatch` | A file was moved or deleted before Auto Loader read it, or the manifest was written but the publish partially failed | `SELECT * FROM control.vw_failed_reconciliations`. Re-run the ADF entity (same run_id, which overwrites the files), then re-run the bronze task. It re-checks until PASSED. |
| 6 | Auto Loader: `UnknownFieldException: new columns found` | The source added a column (`addNewColumns` mode stops the stream once) | Automatic: the task retry picks up the evolved schema. Add the column to `source_registry.yml` if silver needs it (the silver contract doesn't change by itself). |
| 7 | Silver batch fails with `RECON_FAILED` | A bug in the standardize/DQ/dedup chain (rows unaccounted for) | The checkpoint did not advance, so no data is lost. Fix the code, redeploy, re-run: the same batch replays. |
| 8 | Many rows in `quarantine.*` | Upstream data issue, or a new domain value | `SELECT _dq_errors, count(*) FROM quarantine.<t> GROUP BY 1`. Fix at source (CDC brings the correction), or relax or extend the rule via PR if the rule was wrong. |
| 9 | `fact_production_daily` totals don't match silver (SILVER_TO_GOLD FAILED) | A late-arriving dimension (the fact got `-1`) is **not** a mismatch; a mismatch is usually a join fan-out (duplicate current SCD2 versions) | Check `SELECT machine_id, count(*) FROM gold.dim_machine WHERE is_current GROUP BY 1 HAVING count(*) > 1`. Fix, then re-run gold (the CDF watermark was not advanced). |
| 10 | Snowflake publish fails `GOLD_TO_SNOWFLAKE` | A manual change in Snowflake, or a previous MERGE that partially failed | Reset the table's publish watermark: `DELETE FROM control.watermarks WHERE consumer='snowflake_publish' AND source_table='…'`. The next run is a **full** TRUNCATE + reload of that table. |
| 11 | Snowflake auth error `JWT token is invalid` | Key rotated in Snowflake but not in Key Vault, or vice versa | Use `RSA_PUBLIC_KEY_2` for overlap and update the Key Vault secret; no code change. |
| 12 | Power BI shows old data | The refresh task did not run because an upstream reconciliation failed, which is by design | Check the job run and `vw_failed_reconciliations`. Once resolved, re-run from `reconciliation_report`. |
| 13 | IoT: `STREAMING_BACKLOG_SECONDS` alert | Burst of events, or the cluster is too small | Raise `maxOffsetsPerTrigger` or workers. Check that there is no crash loop in the continuous job's run history. |
| 14 | IoT gap: missing minutes for a day | The job was down for more than 7 days, or the watermark dropped very late events | Late events are still in bronze. Replay them via a batch backfill of `silver.iot_sensor_minute_agg` for that day. |
| 15 | Hourly MES tumbling window stuck "waiting on dependency" | The previous hour failed; the self-dependency blocks later hours (by design, to keep CDC ordered) | Fix and rerun the failed window from ADF Monitor. The following windows then run automatically in order. |
| 16 | Silver checkpoint must be reset (for example, a bronze table was rebuilt) | | Delete the checkpoint folder **and bump the quarantine/DQ `txnAppId`** (otherwise the batch ids restarting at 0 are treated as already written). Replay is safe because of the sequence-guarded MERGE. |
